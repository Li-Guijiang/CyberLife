# 视觉识别模块网络请求失败：排查与修复说明

## 1 故障现象

1. 运行 `demos/vision_demo.py`（菜单第 8 项）后，窗口内立即出现红字提示 `Model loading failed - check network`。
2. 控制台输出三次重试，全部失败：

   ```
   WARNING Download failure, retrying 1/3 in 5s https://github.com/ultralytics/assets/.../yolov8n.pt
   SSLError(SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED]
   certificate verify failed: unable to get local issuer certificate (_ssl.c:1081)'))
   ```

3. 摄像头可以打开，但画面里没有任何识别框，识别功能等于完全不可用。

## 2 排查过程与结论

### 2.1 逐项证据

| 序号 | 检查项 | 结果 |
| --- | --- | --- |
| 1 | 直接访问 github.com 是否通 | 通。用 Python 默认 SSL 上下文与 `github.com:443` 握手成功，版本 TLSv1.3 |
| 2 | 用 certifi 证书包访问 | 失败，`unable to get local issuer certificate` |
| 3 | 对端证书签发者 | `CN=SteamTools Certificate, O=BeyondDimension, OU=Technical Department, C=CN` |
| 4 | 本机代理设置 | `HTTP_PROXY` / `HTTPS_PROXY` = `http://127.0.0.1:59366`，即本机在跑 HTTPS 代理 |
| 5 | requests 默认请求 | 失败，`SSLError`；改为 `verify=False` 返回 200 |
| 6 | 原脚本的补丁 | `ssl._create_default_https_context = ssl._create_unverified_context` 对 requests 无效 |

### 2.2 结论：三层原因叠加

1. **直接原因**：本机 HTTPS 代理（SteamTools）在做 TLS 解密，它自签的根证书已装入 Windows 证书库，但**不在 certifi 的 cacert.pem 里**。ultralytics 下载权重走 requests / urllib3，默认只信 certifi，因此证书链校验必然失败。
2. **代码原因**：把"下载预训练权重"放在启动链路上。只要下载环节出任何问题（证书、限流、墙），识别功能整体不可用，而不是降级。同时原脚本试图通过修改 `ssl._create_default_https_context` 绕过校验，这个补丁只影响 urllib 的默认上下文，requests 不读它，所以完全无效。
3. **环境原因**：`yolov8n.pt` 在 GitHub Releases 上，国内网络访问本就不稳定；本次重试三次共 35 秒全部超时/报错。

一句话：**不是"网络断了"，而是证书信任链对不上，加上把下载做成了启动前置条件。**

## 3 修复方案

| 序号 | 措施 | 作用 |
| --- | --- | --- |
| 1 | 默认改用离线检测器 `src/vision_system/object_detect.py`（只用 OpenCV + numpy） | 运行链路彻底无网络，启动即可出结果 |
| 2 | 保留 YOLO 通道，但只从本地 `models/yolov8n.pt` 加载，找不到就提示并自动回退 | 需要 YOLO 时把权重文件拷进来即可，仍不联网 |
| 3 | 新增 `--diagnose` 自检命令 | 一次说清"哪条通道坏、为什么坏"，不下载任何文件 |
| 4 | 给出联网下载的三种正确修法 | 需要下载时有据可依，而不是反复试错 |
| 5 | 检测输出统一为 类别 / 置信度 / 框 / 材质 / 材质置信度，并同时落盘 JSON 与标注图 | 结果可核对、可复核、可入档 |

联网下载的三种正确修法（按推荐顺序）：

1. 手动下载：用浏览器打开 `https://github.com/ultralytics/assets/releases/download/v8.4.0/yolov8n.pt`，存到 `models/yolov8n.pt`，运行时加 `--engine yolo`。
2. 让 requests 信任系统证书库：`pip install truststore`，在程序入口执行 `truststore.inject_into_ssl()`。
3. 导出根证书为 PEM，设置环境变量 `REQUESTS_CA_BUNDLE=<pem 路径>`。

## 4 识别算法说明

### 4.1 候选区域（两路）

1. **颜色路**：把画面按黄橙高可视、红色目标、深色器件、中性浅色四组做 HSV 阈值分割，形态学去噪后取外轮廓。
2. **边缘路**：对 Canny 边缘之外的连通区做区域分割，只收中性色区域。这一路专门解决"灰金属贴在灰墙面"的情况——纯颜色分割会把两者连成一片，而边缘闭合后金属内腔是独立连通区。

两路结果按包围框重合度与尺寸一致性合并，避免同一物体被标签环、镜面高光带切成多个框。

### 4.2 材质判别（金属识别的核心）

对每个区域统计五项光学特征，加权成 0~1 的金属置信度：

| 特征 | 物理含义 | 权重 |
| --- | --- | --- |
| 饱和度均值 S | 金属反射环境色，自身几乎无颜色 | 0.36 |
| 镜面高光占比 | 高亮且不饱和、并且 5 像素内有强亮度台阶，才算高光 | 0.26 |
| 亮度标准差 | 柱面、折面金属沿曲面明暗起伏明显 | 0.20 |
| 内部平整度 | 梯度很小的像素占比，加工面平整 | 0.18 |

两条修正：

1. 平均亮度 ≥ 228 的整片纯白区域（纸、白袋）置信度乘 0.30，避免白纸被判成金属。
2. 深色低饱和、边缘平直的器件（手机、对讲机、镜头）先判为"非金属"，不按裸金属计。

### 4.3 必须说清的局限

单帧可见光图像无法区分"同色系的金属与塑料"（例如拉丝铝与浅灰塑料），本模块给出的是**证据加权的概率判断**，材质置信度低于 0.6 时建议人工复核。金属的最终确认由 `geomagnetic_system` 的电磁探测给出，两者互补而不是互相替代。

## 5 调用的库与各自用途

| 库 | 用途 | 在本模块中的具体调用 |
| --- | --- | --- |
| opencv-python | 图像采集、色彩空间、分割、形态学、轮廓、边缘、直线、纹理、绘制 | `VideoCapture` 摄像头采集；`imdecode` 读中文路径图片；`cvtColor` BGR→HSV/灰度；`inRange` 颜色阈值；`morphologyEx` 开闭运算；`findContours` 轮廓；`Canny` / `Sobel` / `magnitude` 边缘与梯度；`connectedComponentsWithStats` 连通区；`HoughLinesP` 平直边缘；`Laplacian` 纹理方差；`rectangle` / `putText` / `imshow` 绘制与显示 |
| numpy | 掩膜布尔运算与统计量 | 掩膜选取、均值/标准差、`nonzero` 取包围框、掩膜外的像素压平以避免假梯度 |
| pillow | 中文标注（可选） | `ImageFont.truetype` 载入微软雅黑/黑体，`ImageDraw.text` 写字；缺库时自动退回英文标签，不影响检测 |
| argparse / json / pathlib | 命令行、结果落盘、路径处理 | 参数解析、结果写 JSON、批量遍历目录 |

不依赖 ultralytics、torch、requests，也不发起任何网络请求。

## 7 验证结果

用 10 个带真值的合成场景（15 个目标）检验，脚本为 `validate.py`，逐目标比对包围框 IoU 与材质：

| 指标 | 结果 |
| --- | --- |
| 检出率 | 15/15 = 100% |
| 定位 IoU ≥ 0.50 | 15/15 = 100% |
| 材质判别正确 | 11/11 = 100% |
| 虚警 | 1 个 |
| 单帧耗时 | 12~16 ms（640×480） |

说明与已知失效条件：

1. 合成场景用于自检，位置与材质真值在生成时写死，因此指标是"标定集上的结果"，不等于任意真实场景的精度；真实场景请用摄像头模式复核。
2. 已知失效：金属件表面若有一条又宽又硬的镜面高光带，会把一个物体切成两个框（`S08_灰墙上的金属件` 出现 1 个多余框），两框的材质判断仍然都是金属。
3. 本机测试图是合成的，画面质感与实拍有差距；真实场景中光照、遮挡、背景色都会影响效果，阈值需要按现场再标一次。

## 8 与旧版的差异

| 项目 | 旧版 vision_demo.py | 新版 vision_demo.py |
| --- | --- | --- |
| 启动依赖 | 必须联网下载 yolov8n.pt | 零网络，本地检测器 |
| 下载失败时的表现 | 窗口只显示一行红字，识别不可用 | 自动回退离线检测器，识别照常 |
| 网络问题定位 | 只提示"check network" | `--diagnose` 指明是哪条证书链失败 |
| 材质判别 | 无 | 金属/塑料/织物或纸张/非金属，附置信度 |
| 结果输出 | 仅屏幕画框 | 控制台表格 + JSON + 标注图 |
| 动物类别过滤 | 按 COCO 编号硬编码跳过 | 保留原规则，YOLO 通道仍生效 |
